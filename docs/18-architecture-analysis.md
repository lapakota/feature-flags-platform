# Анализ архитектуры платформы feature flags

## Драйверы

- Частые запросы состояний флагов и JSON-конфигов через API.
- Управление флагами через админку: черновики, публикация и история изменений.
- Постепенный rollout с шагом 1% и возможность отката.
- A/B-эксперименты со стабильным назначением варианта пользователю.
- Проверка типа JSON-конфига перед публикацией.

## Сценарии качества

| Стимул                                                                                  | Отклик системы                                                                                  | Мера                                           |
| --------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| Система-потребитель запрашивает флаги при нагрузке 10 000 запросов/с                    | `Delivery Service` отвечает по опубликованной версии без обращения к контуру управления         | p95 времени ответа ≤ 100 мс                    |
| Во время 60-минутного сбоя `Configuration Service` система-потребитель запрашивает флаг | `Delivery Service` отдаёт последнюю опубликованную версию                                       | Доступность чтения ≥ 99,9% во время сбоя       |
| Редактор публикует конфигурацию или откатывает опубликованную версию                    | `Configuration Service` создаёт новую версию, `Delivery Service` начинает отдавать её через API | Не позднее 5 минут для ≥ 99% версий за 30 дней |

## Схемы C4

[Контекстная схема](views/c4-context.md) показывает пользователей, платформу и
внешние системы.

[Контейнерная схема](views/c4-container.md) показывает сервисы, их базы и RabbitMQ.
Подписи на стрелках показывают, чем обмениваются контейнеры. Режим связи виден
по типу стрелки, действия при таймауте указаны под схемой.

## Компромисс

Контур чтения отделён от управления: `Delivery Service` хранит свою копию
опубликованной версии. Чтение не останавливается при сбое управления, и его
можно масштабировать отдельно. Плата за это — задержка применения изменений:
после публикации или отката API чтения некоторое время может отдавать прежнюю
версию. Цель — доставить новую версию за 5 минут в 99% случаев. Кроме того,
нужно обслуживать брокер и повторную доставку сообщений. Решение придётся
пересмотреть, если для аварийного отката потребуется срок строже текущей цели:
5 минут для 99% версий.
