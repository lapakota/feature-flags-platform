# Компромисс: доступность чтения против актуальности

Админка нужна для редактирования флагов и конфигов, а API управления — для их
проверки и публикации. Эти части системы не участвуют в получении состояния
флага.

Система-потребитель отправляет запрос напрямую в API чтения. API чтения
вычисляет ответ по опубликованной конфигурации, которую хранит в собственном
кеше, и не обращается к админке или API управления при каждом запросе.

Если админка или API управления недоступны, потребители продолжают получать
флаги из последней загруженной версии. В это время нельзя опубликовать новые
настройки, поэтому данные в API чтения не изменятся до восстановления контура
управления.

**Что усиливаем.** Доступность и скорость чтения: сбой контура управления не
останавливает получение состояний флагов.

**Чем платим.** Обновление кеша занимает время (до 5 минут). После публикации или отката API
чтения может некоторое время возвращать предыдущую версию.

**Почему это приемлемо.** Флаги читают чаще, чем меняют. Краткая задержка
обновления менее критична, чем недоступность API чтения.
