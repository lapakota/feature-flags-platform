# Архитектура фронтенда админки

## Почему FSD

В админке одни и те же сущности используются на нескольких страницах. Флаг и
версия конфигурации нужны в списке, редакторе и истории, а публикация, rollback
и настройка rollout являются отдельными пользовательскими действиями.

FSD удобно применить, т.к. данная архитектура разделяет эти части по назначению.
Страницы собирают готовые сценарии, действия находятся в `features`, а модели
флагов и версий — в `entities`. За счёт этого логика публикации или rollback не
размазывается по нескольким страницам.

## Карта слоёв и модулей

```text
src/
├── app/
│   ├── routes/                    # маршруты админки
│   ├── providers/                 # подключение API и авторизации
│   └── styles/                    # глобальные стили
├── pages/
│   ├── flags-list/                # список флагов
│   ├── flag-details/              # состояние и настройки флага
│   ├── flag-edit/                 # редактирование флага и конфигурации
│   └── flag-history/              # история и сравнение версий
├── widgets/
│   ├── app-header/                # шапка админки
│   └── flag-summary/              # общая информация о флаге
├── features/
│   ├── create-flag/               # создание флага
│   ├── edit-draft/                # изменение черновика
│   ├── validate-configuration/    # проверка JSON-конфига
│   ├── configure-rollout/         # настройка rollout и вариантов
│   ├── publish-configuration/     # публикация конфигурации
│   ├── rollback-configuration/    # rollback на выбранную версию
│   └── compare-versions/          # сравнение версий
├── entities/
│   ├── flag/                      # модель флага
│   ├── configuration/             # типизированный JSON-конфиг
│   └── configuration-version/     # опубликованная версия
└── shared/
    ├── api/                       # базовый API-клиент
    ├── ui/                        # общие элементы интерфейса
    ├── lib/                       # общие библиотеки
    └── config/                    # настройки приложения
```

Зависимости направлены сверху вниз:

```text
app → pages → widgets → features → entities → shared
```
