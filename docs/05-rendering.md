# Рендеринг админки

## Модель рендеринга

Для админки подойдёт CSR: она доступна ограниченному пулу пользователей только после авторизации, а также не требует SEO.

## Code splitting

- Компонент страницы `/flags/:id/edit` загружается лениво вместе с редактором
  типизированного JSON-конфига. На главной странице со списком флагов редактор не нужен, при этом он может быть относительно тяжёлым.
- Компонент сравнения версий на странице `/flags/:id/history` загружается только после
  выбора двух версий для сравнения. Сам список версий можно показать скачивания кода для просмотра diff.
- Каждую страницу можно тоже лениво подгружать

## Ожидаемый эффект

На основных экранах станет меньше JavaScript для загрузки, разбора и выполнения. LCP уменьшится примерно на `300–700 мс`, а на слабых устройствах —
до `1 с`.

TTFB должен остаться на прежнем уровне: сервер продолжит отдавать тот же статический HTML,
а code splitting влияет на загрузку клиентского кода уже после ответа.
