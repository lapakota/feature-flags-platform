# Надёжность платформы feature flags

## Сбои и тактики

| Сбой                                                            | Тактика                                                                                                                                           |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Delivery Service` перегружен или отвечает слишком долго        | Лимит запросов и таймаут; после серии ошибок обращения временно прекращаются. При отказе API потребитель использует значения флагов по умолчанию. |
| Pod `Delivery Service` завис или перезапустился                 | Проверка готовности и балансировка между рабочими репликами.                                                                                      |
| База `Delivery Service` не отвечает                             | Таймаут; если нельзя проверить ключ API или получить настройки, запрос завершается ошибкой.                                                       |
| API Gateway или Ingress недоступен                              | Несколько реплик и проверка их готовности.                                                                                                        |
| `Configuration Service` недоступен                              | Чтение собственной копии последней опубликованной версии в `Delivery Service`.                                                                    |
| `Auth Service` не отвечает                                      | Таймаут; операции без подтверждённых прав отклоняются.                                                                                            |
| `RabbitMQ` недоступен или версия не дошла до `Delivery Service` | Сохранение исходящего события вместе с версией, повторы с тем же `eventId` и очередь ошибок после исчерпания попыток обработки.                   |
| `History Service` недоступен                                    | Отдельные очереди для истории и доставки версии.                                                                                                  |
| После релиза не загружаются файлы админки                       | Откат файлов в CDN к предыдущему релизу.                                                                                                          |

## Обязательная и необязательная части экрана

Страница истории `/flags/:id/history`.

| Часть экрана                       | Важность       | Поведение при сбое                                                                                                                                                                                        |
| ---------------------------------- | -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Список версий с датой и автором    | Обязательная   | При первом открытии без данных показываются ошибка и кнопка повторить запрос.                                                                                                                             |
| Обновление уже загруженного списка | Необязательная | Если `History Service` подтвердил текущий доступ пользователя к конфигурации, остаётся прежний список с временем загрузки и пометкой «История не обновлена». Без подтверждения доступа данные скрываются. |
| Сравнение двух версий              | Необязательная | Список остаётся доступен, а в блоке сравнения показывается ошибка.                                                                                                                                        |

## Бюджет времени экрана

Плановый бюджет загрузки списка версий — `2,5 с`.

| Этап                                                   |   Лимит | Доля бюджета |
| ------------------------------------------------------ | ------: | -----------: |
| Доставка запроса через API Gateway в `History Service` | `0,4 с` |        `16%` |
| Проверка прав: `History Service` → `Auth Service`      | `0,5 с` |        `20%` |
| Чтение версий из базы `History Service`                | `0,8 с` |        `32%` |
| Возврат ответа и отрисовка списка                      | `0,3 с` |        `12%` |
| Запас на колебания сети и нагрузки                     | `0,5 с` |        `20%` |
| Итого                                                  | `2,5 с` |       `100%` |

Этапы последовательные: `0,4 + 0,5 + 0,8 + 0,3 = 2,0 с`. Остаток — `0,5 с`, или `20%` бюджета.

Повторы входят в лимит своего этапа.

## SLI, SLO и бюджет ошибок

Цели взяты из [дерева полезности](01-utility-tree.md) и [SLI/SLO платформы](10-sli-slo.md). Период — 30 дней.

| Сценарий                         | SLI                                                                 | SLO                                                                    |
| -------------------------------- | ------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Чтение при сбоях управления — S2 | Доля успешных корректных запросов с действующим API-ключом          | Не менее `99,9%` за 30 дней и во время `60`-минутного сбоя управления. |
| Частые запросы флагов — S1       | Доля успешных ответов за время не более `100 мс`                    | Не менее `95%` при нагрузке до `10 000` запросов/с.                    |
| Публикация и откат — S4          | Доля опубликованных версий, доступных через API чтения за `5 минут` | Не менее `99%`.                                                        |

Бюджет ошибок API чтения — `0,1%` корректных запросов.

Для оценки простоя API проверяется чтением тестового флага раз в `30 секунд`. Цель — `99,9%` успешных контрольных интервалов за 30 дней; неуспешная проверка означает недоступный интервал.

Бюджет простоя: `30 × 24 × 60 × 0,001 = 43,2 минуты`. Он считается отдельно от бюджета запросов.

Бюджет тратится на восстановление после неудачного релиза, отказа шлюза, базы или перегрузки.
