# Согласованность данных

## Наборы данных и выбор модели

| Данные                                                   | Кто пишет → кто читает                                                           | Цена устаревшего ответа                                                    | Цена отказа                                                                | Окно расхождения                                 | Модель и причина                                                                                                           |
| -------------------------------------------------------- | -------------------------------------------------------------------------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| Черновики флагов, JSON-конфиги и их схемы                | Редактор через `Configuration Service` → админка                                 | Редактор видит старые настройки и может затереть правку                    | Нельзя сохранить или продолжить редактирование                             | `0 с` после подтверждённого сохранения           | ACID + CP: остановить редактирование лучше, чем потерять изменения.                                                        |
| Исходные опубликованные версии                           | `Configuration Service` → админка и операция отката                              | Редактор видит неверный номер версии и выбирает не то состояние для отката | Публикацию или откат придётся отложить                                     | `0 с` после подтверждения публикации             | ACID + CP: точная версия важнее возможности продолжить работу при сбое.                                                    |
| Копия активной конфигурации и рассчитанные по ней ответы | `Delivery Service` по событию публикации → приложение-потребитель                | Включение, отключение и откат флагов применяются с задержкой               | Приложение использует значения по умолчанию: при `false` фича отключается. | До `5 минут` для `99%` публикаций за 30 дней     | BASE + AP при потере связи с управлением: чтение продолжается по последним полученным настройкам ценой задержки изменений. |
| История изменений                                        | `History Service` по событию изменения → пользователь админки                    | Последнего действия пока нет в списке                                      | Нельзя посмотреть историю и разобраться в изменениях                       | Цель — `60 с` от публикации                      | BASE + AP: прежние записи полезнее недоступного списка.                                                                    |
| Статус применения версии                                 | `Configuration Service` по уведомлению `Delivery Service` → админка              | Версия уже работает, но ещё показано «Применяется»                         | Редактор не может проверить результат публикации                           | Цель — `60 с` от переключения `Delivery Service` | BASE + AP: задержка статуса лучше недоступного результата; ложное подтверждение недопустимо.                               |
| Учётные записи, роли и доступ к конфигурациям            | Администратор через `Auth Service` → `Configuration Service` и `History Service` | Пользователь сохраняет уже отозванный доступ                               | Работа в админке временно недоступна                                       | `0 с` для нового запроса после изменения прав    | ACID + CP: отказ безопаснее доступа к чужим данным.                                                                        |
| Ключи API и разрешённые им конфигурации                  | Администратор → `Delivery Service`                                               | Отозванный ключ продолжает открывать конфигурацию                          | Потребитель не получает флаги через API                                    | `0 с` для нового запроса после отзыва ключа      | ACID + CP: проверка доступа важнее доступности чтения.                                                                     |

Окна `60 с` для истории и статуса — новые плановые цели при работающей связи.
Выдачу и отзыв ключей API предлагается выполнять в `Delivery Service`,
который проверяет их по своей базе без кеширования прав.

## Связь с ADR

Решение соответствует [ADR о разделении управления и чтения](adr/0001-separate-management-and-delivery.md):
при сбое управления `Delivery Service` продолжает отдавать последнюю полученную конфигурацию.
