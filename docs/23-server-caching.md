# Серверное кеширование

## Частота и стоимость чтения

Наборы взяты из [разметки данных](22-data-consistency.md).

| Данные                               | Чтения / изменения за сутки | Чтений на изменение | Одно чтение без кеша       |
| ------------------------------------ | --------------------------- | ------------------- | -------------------------- |
| Черновики, JSON-конфиги и схемы      | 100 / 50                    | 2                   | ≈ 5 мс                     |
| Исходные опубликованные версии       | 200 / 10                    | 20                  | ≈ 10 мс                    |
| Активная копия и рассчитанные ответы | 1 000 000 / 10              | 100 000             | ≈ 20 мс: загрузка и расчёт |
| История изменений                    | 200 / 10                    | 20                  | ≈ 15 мс                    |
| Статус применения версии             | 1 000 / 10                  | 100                 | ≈ 2 мс                     |
| Учётные записи, роли и доступ        | 2 000 / 1                   | 2 000               | ≈ 2 мс                     |
| Ключи API и их разрешения            | 1 000 000 / 1               | 1 000 000           | ≈ 2 мс                     |

## Допустимое устаревание и цена промаха

| Данные                               | Допустимое устаревание                                                             | Промах или чтение без кеша                                         | Решение                                         |
| ------------------------------------ | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------ | ----------------------------------------------- |
| Черновики, JSON-конфиги и схемы      | `0 с` после сохранения                                                             | Чтение из базы, ≈ 5 мс                                             | Без кеша: нужны собственные сохранённые правки. |
| Исходные опубликованные версии       | `0 с` после публикации                                                             | Чтение из базы, ≈ 10 мс                                            | Без кеша: небольшая нагрузка.                   |
| Активная копия и рассчитанные ответы | Доставка за `5 минут` для `99%` публикаций; кеш не добавляет задержку переключения | Загрузка снимка и расчёт, ≈ 20 мс; массовые промахи нагружают базу | Кешировать по номеру версии.                    |
| История изменений                    | Цель — `60 с` от публикации                                                        | Чтение списка, ≈ 15 мс                                             | Без серверного кеша: небольшая нагрузка.        |
| Статус применения версии             | Цель — `60 с` от переключения                                                      | Чтение одной записи, ≈ 2 мс                                        | Без кеша: чтение дешёвое.                       |
| Учётные записи, роли и доступ        | `0 с` после изменения прав                                                         | Проверка по базе, ≈ 2 мс                                           | Без кеша: нельзя задерживать отзыв доступа.     |
| Ключи API и их разрешения            | `0 с` после отзыва ключа                                                           | Проверка по базе, ≈ 2 мс                                           | Без кеша, несмотря на частоту чтения.           |

## Паттерн и вытеснение

Кеш остаётся [в памяти Pod](17-kubernetes.md#состояние-и-готовность)
`Delivery Service`.

| Что кешируется                   | Ключ                                                                                            | Паттерн и вытеснение                                                                        |
| -------------------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Неизменяемый снимок конфигурации | configurationId + version                                                                       | Cache-aside: кеш → при промахе база → запись в кеш → ответ. LRU, TTL `45–60 с`.             |
| Рассчитанный ответ               | configurationId + version + хеш запроса и полного контекста, включая идентификатор пользователя | Cache-aside: кеш → при промахе расчёт по снимку → запись в кеш → ответ. LRU, TTL `45–60 с`. |

Активный номер версии берётся из базы `Delivery Service` и используется в ключе кеша.

## Защита от массовых промахов и инвалидация

| Ситуация                    | Действие                                                                                                                                            |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Первый промах               | Внутри Pod один запрос заполняет кеш по конкретному ключу, остальные ждут результат. Снимок и ответ сохраняются с номером использованной версии.    |
| Новая версия или запуск Pod | Чтобы не перегрузить базу, данные загружаются в кеш с ограничением числа одновременных запросов. Ожидание ограничено таймаутом API.                 |
| Истечение TTL               | Для каждой записи TTL выбирается случайно от `45` до `60 с`, чтобы записи не истекали одновременно.                                                 |
| Публикация или откат        | Обработчик события сохраняет снимок и активный номер версии одной транзакцией. Новые запросы используют ключи новой версии, без очистки всего кеша. |
| Старые записи               | Каждый Pod удаляет их по TTL или LRU.                                                                                                               |
