# Организация фронтенда админки

## Решение

Админка остаётся одним приложением в отдельном репозитории. Для внутреннего разделения используется FSD. Монорепозиторий и микрофронтенды на текущем этапе не нужны.

## Почему выбран монолит

1. **Команды и границы владения.** В проекте не выделены независимые команды для разных частей админки.
2. **Релизный цикл.** Требования выпускать разные экраны независимо друг от друга сейчас нет.
3. **Инфраструктура.** Для статики админки достаточно обычного CDN. При переходе на микрофронтенды каждую часть пришлось бы отдельно собирать, разворачивать и отслеживать – для одного приложения админки это лишнее усложнение. Монорепозиторий тоже не нужен, пока фронтенд приложение одно.
