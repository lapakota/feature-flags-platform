# Развёртывание платформы

## Pipeline

1. В pull request запускаются статические проверки, тесты и сборка.
2. Собираются образы сервисов и статические файлы админки.
3. Собранная версия разворачивается во временной среде, где проходят е2е тесты.
4. После слияния та же версия разворачивается в staging для проверки основных сценариев.
5. Проверенная версия выкатывается в production. При ошибке возвращается предыдущая версия.

## Среды

- `dev` — общая среда для разработки;
- `ephemeral` — временная среда для конкретного pull request;
- `staging` — среда для проверки готовой версии перед релизом;
- `production` — рабочая среда.

## Админка и CDN

SSR здесь нет, так как доступ разрешён только определённым пользователям и нас не интересует трафик из поисковых систем.
Админка работает через CSR, поэтому её HTML, JavaScript и CSS можно хранить как статические файлы и раздавать через CDN.

Ответы `Delivery Service` через CDN не кешируются: они зависят от контекста
пользователя и активной версии конфигурации. Для них у сервиса есть свой кеш.

## Масштабирование

Для сервисов используется горизонтальное масштабирование. В первую очередь оно
понадобится `Delivery Service`, потому что чтений флагов намного больше, чем
изменений конфигурации.

Для баз данных на старте достаточно вертикального масштабирования. Если нагрузки
станет больше, решение можно будет пересмотреть по результатам замеров.
