# Надёжность и наблюдаемость платформы feature flags

API должно быстро отвечать при частом чтении флагов, а публикации и откаты — вовремя доходить до потребителей.

## Сбои и тактики

Сбои и тактики первой очереди перечислены в [документе о надёжности](19-reliability.md#сбои-и-тактики).

## Объекты и метрики

| Объект                            | Модель              | Что измеряется                                                                                                                                                                                                                                                                                      |
| --------------------------------- | ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| API чтения через Ingress          | RED                 | Пользовательские запросы/с; доля ошибок сервера, таймаутов и отказов из-за перегрузки; p95/p99 успешного ответа в мс с учётом времени повторов. Каждый внешний запрос считается один раз.                                                                                                           |
| Доставка версии через `RabbitMQ`  | Four Golden Signals | Трафик — поступления и обработки/с; ошибки — доля неудачных обработок; задержка — p95/p99 от `occurredAt` в [PublishedConfiguration](14-sync-async-contracts.md#событие-publishedconfiguration) до переключения API; насыщенность — число ожидающих и обрабатываемых сообщений, возраст старейшего. |
| Очередь ошибок `Delivery Service` | Four Golden Signals | Число сообщений, поступления/с и возраст старейшего с момента первого попадания в очередь.                                                                                                                                                                                                          |
| Ресурсы Pod и пул соединений БД   | USE                 | Использование — занятая память, ядра CPU и доля занятых соединений; насыщенность — ограничение CPU, нехватка памяти и ожидание соединений; ошибки — завершения из-за нехватки памяти, ошибки и таймауты получения соединений.                                                                       |

## Алерты и первый шаг дежурного

Уведомления получает дежурный платформы.

| Алерт                               | Основание                                                                 | Порог и окно                                                                                                                                                                                                      | Первый шаг                                                                                                   |
| ----------------------------------- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Ошибки или недоступность API чтения | SLO `99,9%`, бюджет ошибок `0,1%`                                         | Ошибок больше `1,44%` одновременно за `1 час` и `5 минут`, минимум `100` корректных запросов в каждом окне; либо `3` неуспешных контрольных чтения подряд                                                         | Проверить Ingress и готовые Pod API Gateway и `Delivery Service`, найти неуспешный запрос в логах и трейсе.  |
| API чтения отвечает медленно        | S1: `95%` успешных ответов за `100 мс`                                    | Больше `5%` успешных ответов медленнее `100 мс` одновременно за `10 минут` и `5 минут`, минимум `100` успешных ответов в каждом окне                                                                              | Найти медленный участок трейса, проверить нагрузку `Delivery Service` и ожидание соединений с базой.         |
| Задержка или ошибка доставки версии | S4: `99%` публикаций за `5 минут`; очередь ошибок требует ручного разбора | Публикация ожидает применения больше `5 минут` в течение `1 минуты`; либо глубина очереди ошибок `Delivery Service` больше `0` в течение `1 минуты`; либо возраст самого старого сообщения в ней больше `5 минут` | Найти версию и событие, проверить исходящую отправку, очередь `Delivery Service` и причину ошибки обработки. |

Порог `1,44%` соответствует расходу `2%` месячного бюджета за час при равномерном трафике: `0,1% × (0,02 × 720) = 1,44%`.

Порог возраста сообщения `5 минут` взят из S4. Непустая очередь ошибок означает, что попытки обработки исчерпаны.

## Цели надёжности и дашборд

Цели взяты из [SLI и SLO платформы](10-sli-slo.md) и [документа о надёжности](19-reliability.md). Период — 30 дней.

| SLI                                                                                                                      | SLO                                                | Бюджет ошибок                                                             |
| ------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------- | ------------------------------------------------------------------------- |
| Успешные корректные запросы / все корректные запросы с действующим API-ключом                                            | Не менее `99,9%`                                   | `0,1%` запросов: до `1 000` неуспешных из `1 000 000`.                    |
| Успешные ответы не медленнее `100 мс` / все успешные ответы                                                              | Не менее `95%` при нагрузке до `10 000` запросов/с | `5%` успешных ответов: до `50 000` медленных из `1 000 000`.              |
| Версии, доступные в API чтения за `5 минут` / все опубликованные версии                                                  | Не менее `99%`                                     | `1%` публикаций: до `10` задержанных или неприменённых версий из `1 000`. |
| Доля доступного времени по контрольному чтению тестового флага каждые `30 секунд`, отдельно от пользовательских запросов | Не менее `99,9%`                                   | `0,1%` времени: `30 × 24 × 60 × 0,001 = 43,2 минуты`.                     |

В SLI доставки учитывается каждая публикация, включая откат. Пропущенная версия тоже расходует бюджет.

Дашборд идёт от состояния внешнего API к его зависимостям:

| Блок сверху вниз           | Вопрос                                      | Что показывается                                                                                                                      |
| -------------------------- | ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Доступность чтения         | Потребитель может получить флаги?           | Успешность запросов, результат внешних проверок, остатки запросного и временного бюджетов.                                            |
| Скорость чтения            | Ответ успевает прийти вовремя?              | Доля ответов до `100 мс`, p95/p99 и остаток бюджета медленных ответов.                                                                |
| Свежесть конфигурации      | Публикация или откат дошли до чтения?       | Доля версий, применённых за `5 минут`, максимальное время ожидания обновления и остаток бюджета публикаций.                           |
| Доставка сообщений         | Где застряло обновление?                    | Поступления и обработки/с, ожидающие и обрабатываемые сообщения, возраст очереди; размер, новые поступления и возраст очереди ошибок. |
| Реплики `Delivery Service` | Хватает готовых копий под текущую нагрузку? | Запросы/с на готовый Pod и число реплик. Порог для [масштабирования](06-deployment.md) определяется нагрузочным тестом по SLO чтения. |
| Ресурсы                    | Что мешает сервису отвечать?                | CPU, память, ожидание соединений БД, ограничения ресурсов и ошибки их использования.                                                  |
